# perl-optree-analyzer 現状レポート (2026-07-05)

Perl の subroutine reference (特に `eval` が返す無名 sub) を受け取り、OP ツリーを
Rust 側で解析して「引数・戻り値仕様 / ガード条件の真理値表 / ベストエフォートの型」を
返す Perl 拡張。計画 (plan.md) のマイルストーン **M0〜M5 まで完了**。
upstream 還元 (libperl-macrogen 0.1.6 / libperl-rs 0.4.1) も一巡し、
本リポジトリは **crates.io 公開版の依存のみでビルド・テストが通る**状態。

## アーキテクチャ

```
crates/
├── analyzer-core     純 Rust (libperl 非依存): ir.rs (SubIr/OpNode/OpDetail),
│                     render.rs (ミニ deparser), dump.rs,
│                     passes/{argspec,retspec,logic,types,lints}.rs
├── analyzer-capture  FFI 層: 生 OP ツリー → SubIr の 2 パスキャプチャ
│                     (capture.rs 507 行 + raw.rs 公式 API 薄層 228 行)
└── analyzer-xs       cdylib (#[xs_sub] + xs_boot!) → blib/arch/.../Analyzer.so
perllib/OpTree/Analyzer.pm   XSLoader + JSON::PP デコードラッパ
```

- **IR は所有型** — pass 1 で pre-order id 採番、pass 2 で op_next/op_other を
  id 解決。以降の解析はインタプリタ非依存の純 Rust。
- **公式 API 原則** — raw.rs は macrogen 生成の公式 API 関数
  (PadnamelistMAX, CvSTART, OpSIBLING, ...) のみ使用。手書きは公開マクロの
  無いもの (op_first, PL_op_name 参照, PadnameFLAGS, PAD_BASE_SV) に限定。
- **ithreads 対応** — const/GV の pad 間接参照、UNOP_AUX の SV item の
  pad offset 格納 (multideref) に対応済み。

## Perl から見た API

| 関数 | 返り値 |
|---|---|
| `analyze($coderef)` | ネイティブ hashref `{args, returns, logic, types, lints}` (XS 直接構築) |
| `analyze_json($coderef)` | 同内容の JSON 文字列 |
| `op_names($coderef)` | 実行順 op 名の arrayref |
| `capture($coderef)` | SubIr 全体 (hashref) |
| `dump_optree($coderef)` | デバッグ用テキストツリー |

非 coderef / XSUB は `#[xs_sub]` トランポリンで croak。

## 解析パスの現状

- **argspec** — 4 段検出: signature (argcheck/argelem aux) → `my (...) = @_` →
  shift/pop 列 → `$_[n]` 直接参照。min/max arity、パラメータ名、デフォルト式。
- **retspec** — `return` 収集 (行番号・値形状) + 暗黙の最終式 + 例外
  (die / Carp::croak / confess) + wantarray フラグ。
- **logic** — 構造的パス解析 v0。文レベルの if/elsif/unless/三項のガードを
  原子条件に分解し、≤8 原子で真理値表を全列挙。
- **types** — フロー非依存の facet 収集 (deref 形状、数値/文字列演算、
  メソッド名集合、PadnameTYPE 宣言型) + 矛盾検出 (例: hashref を
  arrayref として使用、行番号付き)。multideref (`$x->[0]{k}`) デコード込み。
- **lints** — `my $x = EXPR if COND` 検出。

## 既知の制限

- **logic パスは構造的で CFG ベースではない**: next/other エッジ非使用、
  意味的含意なし (`$v>10 ⇒ $v>5` を独立原子として扱う)、式に埋め込まれた
  三項演算子は非対応、ループ条件は対象外。
- **types は v0 のフロー非依存**収集 (代入伝播・分岐考慮なし)。
- PMOP のパターン文字列 (PM_GETRE/RX_WRAPPED) 未デコード — 正規表現は不透明。
- multiconcat の aux 未デコード (不透明フォールバック)。
- パッケージ名 `OpTree::Analyzer` は仮称。CPAN 配布形態 (Makefile.PL 等) は
  未整備で、現状は開発用の make + prove のみ。
- rust-analyzer はこの環境で誤検出あり (proc-macro サーバ不整合) —
  信頼するのは cargo build / test のみ。
