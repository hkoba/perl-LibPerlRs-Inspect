# M6: Makefile.PL ベースのインストール対応 (2026-07-09)

blib 直起動の開発専用ビルドから、`perl Makefile.PL && make && make test && make install`
で実際にインストールできる形へ移行した。方式は **Module::Install::Rust のレシピ
(cargo の cdylib を `$(INST_ARCHAUTODIR)/$(DLBASE).$(DLEXT)` へコピーし `dynamic ::` に
フック) を純 ExtUtils::MakeMaker に翻訳**したもの。

## 構成

- `Makefile.PL` — cargo/perl.h の存在チェック (無ければ CPAN Testers NA 慣行で exit 0)、
  `--debug` で dev プロファイル (デフォルト release)、MY::postamble で cargo 統合
- `perllib/` → `lib/` (EUMM 標準レイアウト)、手書き Makefile は撤去
- `MANIFEST` / `MANIFEST.SKIP` — Cargo.lock を dist に同梱 (`--locked` ビルドの前提)
- `README.md` — ビルド要件 (cargo ≥1.85 / perl-devel / libclang) とビルド時の
  crates.io ネットワーク要件、オフライン手順 (cargo vendor)
- `test.zsh` — `[[ -f Makefile ]] || perl Makefile.PL --debug; make test` の薄いラッパ
- 上流: **libperl-config 0.3.3** (libperl-rs 73b1776) — `PerlCommand::default()` が
  `PERL` 環境変数を優先 + `cargo:rerun-if-env-changed=PERL`。postamble の
  `PERL=$(FULLPERL)` により「Makefile.PL を実行した perl」と「cargo が bindgen/link
  する perl」が一致する。publish 前でも `dirname $(FULLPERL)` の PATH 前置で動作

## 検証済み (2026-07-09)

- `perl Makefile.PL --debug && make && make test` — 72 テスト PASS
- `make realclean && perl Makefile.PL && make -j4 && make test` — release + 並列 PASS
- `make install DESTDIR=<stage>` → リポジトリ外 cwd から `PERL5LIB=<sitearch>` で
  analyze()/op_names() 動作。.packlist / Analyzer.so / man3 配置正常
- `make distcheck` クリーン、`make disttest` PASS、`make dist` → tarball (53KB) を
  展開して `cpanm -l <ll>` で configure→build→test→install 一気通貫、local::lib
  経由で signature 解析まで動作確認
- `PERL=/nonexistent/perl cargo build` が正しく失敗 (env var が効いている証拠)

## 落とし穴 (EUMM 7.76 ソース裏取り済み、再発防止用)

1. **`linkext => { LINKTYPE => '' }` は使用禁止** — `pure_all → linkext → dynamic` の
   連鎖が切れて postamble のフックが make から呼ばれなくなる (7.x では警告も出る)
2. **`--debug` を @ARGV から strip しない** — Makefile 再生成ルールは @ARGV 原文を
   埋め込むため、strip すると Makefile.PL 更新時の再生成で release に化ける
   (非 KEY=VALUE 引数は EUMM が黙って無視するので放置が正しい)
3. **EUMM の `$(FULLPERL)` はクォート込み**で展開される — postamble 側で重ねて
   クォートすると空白入りパスで壊れる
4. **blibdirs は .PHONY** — file ルールの依存に使わず自前 `$(MKPATH)` (-j 安全)
5. **libperl-config 0.3.3 publish 後は `cargo update -p libperl-config` 必須** —
   `--locked` により lock の 0.3.2 が使われ続け PERL env が無視される
   (開発機では PATH の perl が偶然一致して気付きにくい)
6. `make disttest` は DISTVNAME 内に巨大な target/ を残す — 手動で rm
7. `clean` では cargo clean しない (bindgen/macrogen 再生成が高コスト)。
   `realclean ::` のみで実行
